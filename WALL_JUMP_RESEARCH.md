## What the referenced build does

The local 1.3.2 artifact and the upstream description agree on the core loop:

1. Jump toward a wall and hold the wall-jump control. The default control is left Shift; the mod can be configured to use Space instead.
2. While airborne, the client checks a thin collision area around the player at approximately eye-height, with probes on the positive-Z, negative-X, negative-Z, and positive-X sides.
3. When a wall is found, horizontal motion is suppressed and the player clings. Upward motion is stopped. A fast downward velocity is softened, then a delayed slow slide begins.
4. Releasing the wall-jump control launches the player away from the wall. The inspected defaults are a vertical boost of `0.55`, a slide delay of `15` ticks, and re-clinging disabled until the player has dropped roughly one block or has moved to another wall.
5. Water, being on the ground, flying, and the mod’s hunger restriction clear or prevent the wall state. The mod also has optional features such as double-jump, step assist, automatic rotation, enchantments, and exhaustion; those are separate features and are not silently enabled by this request.

The inspected class behavior includes the following defaults:

| Setting or behavior | Referenced 1.3.2 default | JasperCraft implementation |
| --- | ---: | --- |
| Wall-jump feature | enabled | enabled by default in `wall-jump.enabled` |
| Wall-jump vertical boost | `0.55` | `0.55` |
| Wall-slide delay | `15` ticks | `15` ticks |
| Re-cling the same wall | disabled | disabled until a one-block drop or a different wall |
| Wall slide speed after delay | `-0.1` Y/tick | `-0.1` Y/tick |
| Fast-fall correction | add `0.2` to Y when below `-0.6` | same rule |
| Horizontal jump strength | `0.45 × boost` | `0.45 × boost` |
| Access requirement | client key/config; no item in core behavior | no item, armor, permission, or authentication requirement |
| Release direction | tied to client movement input | freshest horizontal movement intent, then facing direction fallback |

## Implementation decision

I chose an independent server-side port of the behavior rather than copying the JAR. This is the best fit for the current architecture:

- The plugin already owns authoritative movement-adjacent gameplay and runs on the patched Paper 1.12.2 server.
- Every online player is polled, including guests and players who have not authenticated through the plugin’s survival systems. Spectators, flyers, vehicle passengers, grounded players, and players in water are safely excluded from an airborne cling.
- The server receives the normal sneak state generated by keyboard and touch controls. No Forge mod, resource pack, browser patch, or special item is needed.
- The original launch direction is preserved: recent horizontal movement deltas and velocity are recorded before/while clinging. If collision has reduced those to zero, the player’s horizontal facing direction is used. This prevents the server from imposing a backwards wall-normal kick.
- Collision is checked with the server’s existing NMS `getCubes` API. A cling anchors horizontal movement through `PlayerMoveEvent` and applies velocity through Bukkit, keeping the server authoritative if client prediction differs.
- The implementation is small and bounded: one scheduled tick per online player and up to four thin wall probes. It does not load distant chunks or add HTTP telemetry.

The main files are:

- `server/custom-plugins/JasprApocalypse/src/chat/jaspr/apocalypse/WallJumpController.java` — lifecycle, player state, collision probes, sneak events, movement anchoring, and metrics.
- `server/custom-plugins/JasprApocalypse/src/chat/jaspr/apocalypse/WallJumpRules.java` — dependency-free slide, launch, and re-cling calculations.
- `server/custom-plugins/JasprApocalypse/src/chat/jaspr/apocalypse/ApocalypsePlugin.java` — starts/stops the controller and includes its metrics in `/apocalypse status`.
- `server/custom-plugins/JasprApocalypse/resources/config.yml` — defaults and bounded tuning values.

## Player controls

- Airborne near a wall: hold the normal sneak control (`Shift` on desktop; the client’s native sneak control on mobile).
- While clinging: remain held to the wall for the delay, then slide slowly downward.
- Release sneak: wall-jump away from the detected wall.
- To re-cling the same wall after jumping: drop about one block first. A different contacted wall can be used immediately.

Because the server does not receive a raw per-key W/A/S/D stream, release does not require a desktop-only forward-key check. The launch uses the freshest horizontal movement intent observable in server movement packets, then the player’s facing direction when the wall has stopped movement. This is an intentional compatibility adaptation, not a claim that the server sees the original mod’s individual key state.
