# Guns reload themselves, the Portal Gun alternates, Sanitized Flesh is jerky (2026-10-05)

Three owner requests, one change set (branch `claude/guns-portal-jerky`; JasprApocalypse 3.7.3, JasprDungeon 6.0.2, client key `20261005-guns1`).

## 1. Guns reload automatically

> "Guns should reload automatically when their magazine is empty, provided there are enough bullets in your inventory. Still
> preserve the shift-reload, just in case you want to reload when your magazine isn't fully empty yet."

**Expedition firearms** (`JasprApocalypse` `Arsenal.java`, 40 guns): the shot that empties the magazine starts the normal timed
reload by itself (`autoReload`), and so does the last shot of a burst; a plain right-click on an empty gun starts it too (it used
to say "sneak + right-click to reload"). The reload is the same timed one as before -- ammunition is only taken when it
completes, switching slot or travelling cancels it, `reloading` / `bursting` / `readyAt` are respected -- and it only starts when
plain, unmarked iron nuggets for one round are carried (marked Military Salvage is not ammunition). With no ammunition the player is
told once ("... is empty and you have no iron nuggets to load it."). Sneak + right-click still reloads a magazine that is not
empty yet. The lore line, the guide book's "LOADING & FIRING" page and the item guide say so.

**Dungeon armoury guns** (`JasprDungeon` `Arsenal.java`): a trigger pull on too few rounds already reloaded; now the pull that
leaves the magazine unable to pay for another one queues a `Pending` reload job (due after the shot's recovery and burst), which
re-checks everything when it fires (same gun and serial in hand, still short, not reloading, plain nuggets carried).

Tests: `tests/guns-smoke.cjs` runs `GunsProbe` on a real Paper server (233 assertions): every one of the 40 guns reloads on an empty
click and on its last round, cancellation, no ammunition, marked salvage, fewer nuggets than one round costs, rounds left (fires,
does not reload), sneak reload early, a burst gun's last shot. `tests/gun-reload-portal.test.cjs` pins the source contracts
(including the Dungeon path, which has no runtime probe: it compiles and is reviewed, and its queue is bounded by the armoury's own
`MAX_PER_PLAYER`).

## 2. The Portal Gun

> "I want you to rework how it works when shooting two portals. It should just alternate between blue and orange. There should be
> no shift-click necessary because it just alternates every time you place a portal."

`PortalGun.java`: each owner has a pair (`blue`, `orange`) and a `nextOrange` flag. A shot that finds a surface opens the portal
of the colour whose turn it is, then passes the turn (blue, orange, blue again -- which moves the blue portal -- and so on); a shot
that finds no surface keeps its turn. Sneaking changes nothing. Portals are drawn in blue `{30,144,255}` and orange `{255,140,0}`;
the action bar says which was set, whether the pair is linked and which colour is next. Guns made before this change get today's
lore (`ExpeditionEquipment.refreshPortalGunLore`, on join and plugin start; serial, tier and model band untouched). The earlier cyan
and amber colours are gone everywhere.

> "The texture looks really bad, and it should be redone to look better. The model should be better."

The old model stretched six vanilla block textures over 20 plain boxes. The new one is original art generated by
`apocalypse-pack/portal-gun-art.cjs` (`portal-gun-model.cjs` delegates to it): a white ceramic shell over a graphite chassis,
brushed steel fittings, a rubber grip, a glowing blue / orange split rail on top, two 16-sided energy cells (blue on the left flank,
orange on the right) feeding an emitter cage whose lens is split blue and orange, a side screen showing two overlapping portal rings.
66 cuboids; the round parts are regular polygons made of slabs (`tube`, covering exactly the polygon: tested). Every visible face
gets its own painted patch of one 128x128 texture (`textures/items/apocalypse_portal_gun.png`, about 3.5 texels per model unit,
MaxRects-packed, one texel gap that is filled by the neighbouring colour so a sample that lands just outside a face never finds a
hole, every patch fully painted, bevels blended into the faces so the item does not sparkle when drawn small with mipmaps off). The
held-item contract is unchanged (barrel -Z, grip -Y, same hand transforms), so the existing hand-orientation tests still apply; only
the inventory icon changed: it keeps the other guns' rotation (muzzle to the upper left) but its scale and centring are computed
from the model's projected extent so it fills the slot (the old icon used 58% of it).
Checked in the real client (`tests/guns-art-browser.cjs`): the inventory slot, and the gun held in first person. `scripts/model-preview.cjs` is a small software renderer of 1.12
item models (the game's UV and facing conventions, mip levels, display transforms) used to design and check it without a client:
`node scripts/model-preview.cjs <model.json> <textures dir> <out.png> gui side iso top`.

`scripts/merge-apocalypse-assets.cjs` now also carries a pack's `textures/items/*.png`; `scripts/build-apocalypse-pack.cjs`
allows the Portal Gun's own texture and up to 80 cuboids / omitted hidden faces for that one model (everything else keeps the strict
rules).

## 3. Sanitized Flesh is jerky

> "sanitized flesh should have its own texture, and it should look like jerky"

Sanitized Flesh is a stackable cooked beef: vanilla can only pick a model by damage, and only for damageable items, so the carrier
trick of the trinket icons does not work. Instead the client got a small **NBT-skin stage** (`client-mods/nbt-skin-teavm.js`, built
by `scripts/build-nbt-skin-client.cjs`, fenced `JASPR_NBTSKIN`, marker `JN`):

* `Items.<clinit>` (`F7x`) hands the cooked beef to `JasprNbtSkinInstall`, which registers a property getter named `jaspr_skin`
  (`DQE` = `Item.addPropertyOverride`); that also makes the renderer evaluate the item's model overrides at all.
* The getter reads the id the stack's own data carries -- `JasprApocalypse.id` (what the server and the Easier Crafting recipe book
  write) or `JasprCreative.id` (the creative catalogue placeholder) -- and answers the number `JasprNbtSkinTable` gives it
  (`{sanitized_flesh: 1}`), else 0. Nothing about the item changes: no new NBT, same stacking, same behaviour, and items made before
  the stage existed are skinned the moment they are seen (no migration).
* `cooked_beef.json` gains one override, `{"predicate": {"jaspr_skin": 1}, "model": "item/jaspr_sanitized_flesh"}`.

The icon (`scripts/supply-art/jerky.cjs`, 16x16, deterministic) is a bundle of three dark dried-meat strips tied with twine. To skin
another stackable supply the same way, add its id to `JasprNbtSkinTable` with the next number, install the getter on its item in
the stage's hook, and add an override with that number to the item's model.

`scripts/build-guns-pack.cjs` merges the jerky texture and model, `cooked_beef.json` (the archive's own, plus the override) and the
Portal Gun's model and texture into the live archive; idempotent, selector proof included.

## Rebuild order and ownership

Client: LIVE `classes.js` -> `build-nbt-skin-client.cjs` (a fenced block before the TeaVM footer plus one marked call; it does not
overlap any other stage, so it can be applied or removed on its own: `--unpatch`). LIVE `assets.epk` -> `build-guns-pack.cjs` (this
update owns `cooked_beef.json` and the two `jaspr_sanitized_flesh` files; the Portal Gun files are the apocalypse pack's).
`node scripts/assemble-guns-client.cjs --game <live checkout> --out candidate/deploy --key <key>` builds both plus the two cache
keys from the live files. Plugin jars: `node scripts/patch-plugin-jars.cjs --game <live checkout> --out candidate/jars
JasprApocalypse JasprDungeon`.
